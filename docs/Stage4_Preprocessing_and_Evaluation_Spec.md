# CreditLens 전처리·평가 체계 명세

> V1·V2·V3 고객 분석 마트에 동일하게 적용할 전처리 경계와 평가 지표의 계산 계약을 정의합니다. 실제 기준 모델 성능은 별도 실행 보고서에 기록하며, 이 문서는 최종 피처, 확률 보정과 의사결정 cutoff를 확정하지 않습니다.

## 1. 목적

- 학습 데이터에서만 전처리 규칙을 학습해 validation과 향후 test로의 데이터 누수를 방지합니다.
- V1·V2·V3와 서로 다른 모델을 같은 분할·피처 제외 정책·지표 정의로 비교할 수 있게 합니다.
- 결측, 구조적 해당 없음, 희소범주와 미등록 범주의 의미를 구분합니다.
- 불균형 이진분류에 필요한 지표의 산식, 임계값과 Top-K 동점 처리 방식을 고정합니다.
- 교차검증에서도 전처리와 모델이 하나의 파이프라인으로 함께 학습되도록 합니다.

## 2. 입력 데이터 버전

| 버전 | 역할 | 전체 형태 | 후보 피처 | 정책 제외 후 모델 입력 후보 |
|---|---|---:|---:|---:|
| V1 | 현재 대출 신청정보 기준선 | 307,511행 × 136열 | 133 | 132 |
| V2 | V1 + 외부 신용이력의 추가 가치 측정 | 307,511행 × 173열 | 170 | 169 |
| V3 | V2 + 과거 납부행동의 추가 가치 측정 | 307,511행 × 202열 | 199 | 198 |

후보 피처 수는 `SK_ID_CURR`, `TARGET`, `SPLIT`을 제외한 값입니다. 정책 제외 후 수는 여기에 `CODE_GENDER` 제외를 반영한 값이며 최종 피처 선택 결과가 아닙니다.

각 데이터 버전은 별도의 전처리 파이프라인을 사용합니다. V1에서 학습한 중앙값·범주 목록·스케일 값을 V2나 V3에 재사용하지 않으며, 각 버전의 train에서 독립적으로 학습합니다.

기본 마트 경로를 읽을 때는 Stage 3 구축 요약과 정확한 스키마 해시, 전체·split별 행 수, Parquet SHA-256을 자동으로 대조합니다. 같은 개수와 자료형을 유지하더라도 컬럼이 바뀌거나 고객 행이 빠진 마트는 모델 입력 전에 거부합니다.

## 3. 데이터 사용 경계

| split | 고객 수 | 허용 작업 | 금지 작업 |
|---|---:|---|---|
| train | 215,258 | 전처리 `fit`, 교차검증, 이후 모델 학습 | 원본·마트 수정 |
| validation | 46,127 | train에서 학습한 파이프라인의 `transform`, 이후 후보 비교 | 전처리 `fit`, 희소범주·스케일·대치값 결정 |
| test | 46,126 | 고객 수·키 유일성·split 구성 등 메타데이터 검증 | 피처·정답 로드, 변환·EDA, 모델 예측·평가·선택 |

### test 봉인

test는 Stage 8에서 모델, 전처리, 확률보정과 cutoff를 모두 고정한 뒤 한 번 평가합니다. 현재 Stage 4 실행 경로는 train과 validation 피처만 읽고 다음 조건을 보장해야 합니다.

- test 피처 행 디코딩·조회: 0행
- test 전처리 변환: 0행
- test 예측·지표·그래프 생성: 없음
- test 고객 수·키 유일성·split 구성: 분할 계약 확인용 메타데이터로만 검증

test의 피처와 정답은 DuckDB 컬럼으로 디코딩·조회하지 않습니다. 분할 계약 검증은 식별자와 split 메타데이터만 사용합니다. Parquet SHA-256 검증은 파일 전체의 원시 바이트를 읽지만 test 값을 통계·변환·모델 선택에 사용하지 않습니다.

validation의 수치·범주 값을 바꿔도 train에서 학습된 대치값, 희소범주 목록, 인코더 범주, 스케일 값과 피처 순서가 바뀌어서는 안 됩니다. test 값은 현재 실행 경로의 이 불변성 검증에도 사용하지 않습니다.

## 4. 모델 입력 제외 정책

| 제외 대상 | 이유 |
|---|---|
| `SK_ID_CURR` | 고객 연결·추적용 식별자이며 일반화 가능한 설명변수가 아님 |
| `TARGET` | 정답 레이블이며 입력에 포함하면 직접 누수 |
| `SPLIT` | 분할 메타데이터이며 고객 특성이 아님 |
| `CODE_GENDER` | 직접적인 성별 사용을 피하기 위한 프로젝트 정책 |
| 그 밖의 `SK_ID_*` 컬럼 | 예상하지 못한 식별자 컬럼은 스키마 계약 위반으로 보고 로더에서 거부 |

`TARGET`은 train과 validation에서 이진 정답 벡터 `y`로만 분리합니다. `SK_ID_CURR`과 `CODE_GENDER`는 로컬 품질·공정성 점검에 사용할 수 있지만 전처리기와 모델에는 전달하지 않습니다. 제외한 컬럼은 변환 후 피처 이름에도 나타나지 않아야 하며, 계약에 없는 `SK_ID_*` 컬럼은 자동 제외하지 않고 입력 오류로 처리합니다.

## 5. 수치형 전처리

### 일반 결측

1. train `fit` 시 결측이 관측된 수치 피처에 한해 대치 전 결측 여부를 별도 0/1 indicator로 만듭니다.
2. 관측값이 있는 피처의 결측은 해당 학습 집합에서 계산한 중앙값으로 대치합니다.
3. 한 학습 집합에서 전체가 결측인 피처는 중앙값을 계산할 수 없으므로 결측값을 0으로 채웁니다.
4. 전체 결측 피처도 결측 indicator를 유지해 0이 실제 관측값이라는 잘못된 의미를 만들지 않습니다.
5. validation의 결측에는 train에서 저장한 대치값만 적용하며 validation에서 중앙값을 다시 계산하지 않습니다.
6. 실제 0은 결측으로 바꾸지 않습니다.

indicator 대상과 출력 열은 train `fit` 결과로 고정합니다. 따라서 train에서 결측이 없던 피처에 validation 결측이 처음 나타나면 train에서 학습한 값으로 대치하되, validation 정보만으로 새로운 indicator 열을 만들지 않습니다. 이 경우의 신규 결측 발생은 출력 스키마를 바꾸는 대신 별도의 데이터 품질 점검 대상으로 다룹니다.

### 이력 없음

`BUREAU_HAS_HISTORY=0`, `INST_HAS_HISTORY=0`과 이력 건수 0은 관측된 업무 상태이므로 그대로 유지합니다. 이력이 없어서 금액·평균·비율이 `NULL`인 경우에는 일반 결측 규칙으로 대치하되 원본 결측 indicator와 `HAS_HISTORY`를 함께 보존합니다.

이 방식은 다음 두 상태를 구분합니다.

```text
관측된 값이 실제 0
이력이 없거나 원천 값이 관측되지 않아 대치된 0·중앙값 + 결측 indicator 1
```

### `OWN_CAR_AGE` 구조적 해당 없음

차량 미보유자의 차량연식 결측은 일반적인 정보 누락과 다르게 처리합니다.

1. `OWN_CAR_AGE_NOT_APPLICABLE=1`이면 `OWN_CAR_AGE`를 0으로 채웁니다.
2. `OWN_CAR_AGE_NOT_APPLICABLE` 플래그는 모델 입력에 유지합니다.
3. 차량 보유자의 실제 연식 결측은 `OWN_CAR_AGE_MISSING=1`로 구분하고 train의 유효 차량연식 중앙값으로 대치합니다.
4. 구조적 해당 없음과 차량 보유자의 결측은 같은 상태로 합치지 않습니다.
5. 두 플래그는 결측 없는 0/1이어야 하며 연식 값과 플래그가 모순되면 입력 오류로 처리합니다.

### 무한값과 이상값

- `inf`, `-inf`와 숫자 컬럼의 문자열 혼입은 입력 계약 오류로 처리합니다.
- 극단값만으로 고객 행을 삭제하지 않습니다.
- 공통 기반 파이프라인에서는 `log1p`와 분위수 clipping을 적용하지 않습니다. 해당 변환은 이후 선형 모델 개선 실험에서 train 내부 비교 대상으로만 다룹니다.
- 납부비율은 실제 초과납부로 1보다 클 수 있으므로 일괄적으로 0~1 범위에 자르지 않습니다.

## 6. 범주형 전처리

처리 순서는 결측 명시화, 희소범주 통합, 원-핫 인코딩입니다.

### 결측과 원본 범주

- 실제 결측은 문자열 `__MISSING__`으로 바꿉니다.
- 원본의 `Unknown`, `XNA`는 실제 관측 범주이며 자동으로 결측과 합치지 않습니다.
- `__MISSING__`, `__RARE__`는 예약 토큰으로 관리하며 원본 값과 충돌하면 입력 계약 오류로 처리합니다.

### train 희소범주

- 현재 `fit`하는 학습 집합에서 관측 비율이 **0.1% 미만**인 범주를 `__RARE__`로 합칩니다.
- 경계값과 대상 범주 목록은 train에서만 학습합니다.
- 교차검증에서는 전체 train의 목록을 미리 만들지 않고 각 fold의 학습 부분에서 다시 계산합니다.
- 원본의 `Unknown`, `XNA`도 관측 비율이 기준보다 낮으면 일반 범주와 같은 규칙으로 `__RARE__`에 포함될 수 있지만 `__MISSING__`으로 취급하지는 않습니다.

희소 기준은 비율 `< 0.001`을 엄격하게 적용합니다. 기준과 정확히 같은 비율은 희소범주로 합치지 않습니다.

### 미등록 범주

train에 없고 validation에서 처음 나타난 범주는 새로운 열을 만들지 않습니다. 원-핫 인코더는 `handle_unknown="ignore"` 규칙을 사용하며 해당 범주의 원-핫 부분을 모두 0으로 변환합니다.

미등록 범주는 train에서 관측된 희소범주와 다르므로 자동으로 `__RARE__`에 매핑하지 않습니다. 이 규칙으로 validation 정보가 범주 목록이나 출력 스키마를 바꾸는 것을 막습니다.

## 7. 모델 계열별 변환

### 공통 출력

- 전처리 출력은 SciPy CSR 형식의 희소 행렬을 기본으로 합니다.
- 출력 자료형은 `float32`로 고정합니다.
- train과 validation의 열 수, 열 순서와 피처 이름이 같아야 합니다.
- 출력에는 `NaN`, `inf`, `-inf`가 없어야 합니다.
- 원-핫 범주와 결측 indicator 때문에 출력 열 수는 입력 마트의 피처 수보다 늘어날 수 있으며 train `fit` 결과로 확정됩니다.

### 선형 모델용 파이프라인

- 수치형 대치 후 `StandardScaler(with_mean=False)`를 적용합니다.
- 중앙값을 빼지 않아 희소 행렬을 유지하면서, 드물게 큰 값이 나타나 사분위 범위가 0인 금액 피처도 표준편차 기준으로 크기를 맞춥니다.
- 범주형 원-핫 값과 0/1 indicator에는 별도의 스케일링을 적용하지 않습니다.

### 트리 모델용 파이프라인

- 수치형 대치, 결측 indicator와 범주형 원-핫 인코딩은 동일하게 적용합니다.
- Random Forest 등 트리 모델에는 수치 스케일링을 적용하지 않습니다.

두 파이프라인은 제외 컬럼, 결측 의미, 범주 목록과 출력 자료형 계약을 공유합니다. 모델 계열별 차이는 수치형 스케일링 여부뿐입니다.

## 8. 파이프라인과 교차검증 경계

학습 가능한 모든 변환은 모델과 하나의 scikit-learn `Pipeline` 안에 있어야 합니다.

```text
입력 컬럼 선택
  → 결측·구조적 해당 없음 처리
  → 희소범주 목록 학습
  → 범주 인코딩
  → 모델 계열별 수치 스케일링
  → 모델
```

- 고정 train/validation 비교에서는 전체 train에 파이프라인을 `fit`하고 같은 객체로 validation을 `transform`·예측합니다.
- 교차검증에서는 각 fold의 학습 부분에 파이프라인 전체를 `fit`합니다.
- 대치값, 희소범주, 인코더 범주, 스케일 값과 모델 파라미터를 fold 바깥에서 미리 계산하지 않습니다.
- validation에는 전처리기나 모델을 `fit`하지 않습니다.
- test를 받거나 변환하는 Stage 4 공개 함수는 제공하지 않습니다.

## 9. 평가 입력 계약

- `y_true`는 결측이 없는 0/1 값이어야 합니다.
- `y_score`는 `TARGET=1`의 예측확률이며 모든 값이 유한한 0~1 범위여야 합니다.
- `y_true`와 `y_score`의 길이는 같아야 합니다.
- ROC-AUC와 KS 계산에는 두 클래스가 모두 존재해야 합니다.
- 분류 임계값과 Top-K 비율은 명시적으로 전달하며 함수 내부에서 validation 결과에 맞춰 자동 탐색하지 않습니다.

## 10. 공통 평가 지표

아래에서 `y_i`는 실제 `TARGET`, `p_i`는 `TARGET=1` 예측확률, `N`은 평가 고객 수입니다.

### ROC-AUC

무작위로 뽑은 `TARGET=1` 고객의 점수가 무작위 `TARGET=0` 고객보다 높을 확률로 해석합니다. 점수가 같은 쌍에는 0.5를 부여하는 표준 ROC-AUC를 사용합니다.

### PR-AUC

CreditLens의 PR-AUC는 사다리꼴 보간 면적이 아니라 scikit-learn `average_precision_score`와 같은 **Average Precision(AP)** 방식으로 정의합니다.

```text
AP = Σₙ (Recallₙ - Recallₙ₋₁) × Precisionₙ
```

결과 필드는 `pr_auc`로 기록합니다. 클래스 불균형을 고려해 양성 비율을 무작위 기준선으로 함께 보고하며, `pr_auc`의 계산 정의는 AP로 고정합니다.

### KS

점수가 높은 고객부터 낮은 고객 순으로 모든 고유 점수 임계값을 적용하고, 각 임계값에서 양성 누적비율과 음성 누적비율의 방향성 차이가 가장 큰 값을 계산합니다.

```text
KS = maxₜ (TPR(t) - FPR(t))
```

절대값을 사용하지 않으므로 점수 방향이 반대로 된 모델을 좋은 분리력으로 오인하지 않습니다. KS를 계산하기 전에 점수를 반올림하지 않으며, 같은 점수는 하나의 임계값 그룹으로 처리합니다.

### Gini

동일한 예측점수의 ROC-AUC에서 다음 식으로 계산합니다.

```text
Gini = 2 × ROC-AUC - 1
```

Gini는 ROC-AUC와 독립적인 별도 성능으로 해석하지 않습니다.

### Brier Score

예측확률과 실제 정답의 평균제곱오차입니다. 값이 작을수록 확률 오차가 작습니다.

```text
Brier = (1 / N) × Σᵢ (pᵢ - yᵢ)²
```

### 임계값 기반 분류 지표

명시된 임계값 `c`에 대해 다음 규칙을 사용합니다.

```text
예측 양성 = pᵢ >= c
예측 음성 = pᵢ < c
```

Recall, Precision과 F1을 계산하고 Confusion Matrix는 `[[TN, FP], [FN, TP]]` 순서로 기록합니다. 임계값과 정확히 같은 점수는 양성에 포함합니다.

## 11. Top-K 지표와 경계 동점

평가 비율을 `q`, 고객 수를 `N`이라 할 때 목표 검토 인원은 다음과 같습니다.

```text
K = max(1, ceil(N × q))
```

점수를 내림차순으로 정렬했을 때 K번째 경계 점수에 동점이 없으면 상위 K명을 선택합니다. 경계에 동점이 있으면 임의의 행 순서로 일부 고객을 고르지 않고 **fractional tie**를 적용합니다.

- 경계 점수보다 높은 고객 수를 `H`라고 합니다.
- 경계 점수와 같은 고객 수를 `T`라고 합니다.
- 남은 자리 `K - H`를 동점 고객에게 동일하게 배분합니다.
- 동점 고객 한 명의 선택 가중치는 `w = (K - H) / T`입니다.
- 경계보다 높은 고객은 가중치 1, 낮은 고객은 0을 사용합니다.

가중 양성 수를 `TP_K`라고 할 때 지표는 다음과 같습니다.

```text
Recall@TopK    = TP_K / 전체 TARGET=1 고객 수
Precision@TopK = TP_K / K
Lift@TopK      = Precision@TopK / 전체 TARGET=1 비율
```

이 방식은 경계 동점에서 입력 행 순서가 결과를 바꾸지 않으며 유효 선택 인원을 정확히 K로 유지합니다. `q`는 0보다 크고 1 이하여야 합니다.

## 12. 자동 검증 계약

전처리와 평가 모듈은 최소한 다음 조건을 자동 테스트해야 합니다.

- validation 값을 바꿔도 train에서 학습한 전처리 상태가 변하지 않음
- Stage 4 실행에서 test 피처 행 디코딩·조회와 변환이 0행임
- 기본 마트의 스키마·행 수·split별 건수·파일 해시가 Stage 3 구축 요약과 일치함
- 식별자, `TARGET`, `SPLIT`, `CODE_GENDER`가 출력 피처에 없음
- 실제 0, 일반 결측, 이력 없음과 차량연식의 구조적 해당 없음이 구분됨
- `__MISSING__`, `__RARE__`, 원본 `Unknown`·`XNA`와 미등록 범주가 계약대로 처리됨
- train과 validation 원본 값이 예약 범주 토큰과 충돌하면 거부됨
- 선형 모델에서도 결측 indicator가 스케일되지 않고 0/1을 유지함
- train과 validation 변환 결과의 열·순서·이름이 같고 값이 유한한 `float32` 희소 행렬임
- 교차검증 fold 밖의 통계가 전처리 `fit`에 사용되지 않음
- ROC-AUC, AP, KS, Gini, Brier와 임계값 지표가 작은 합성 예제의 수기 계산과 일치함
- Top-K 경계 동점에서 행 순서를 바꿔도 fractional tie 결과가 같음
- 잘못된 스키마·정답·확률·임계값·Top-K 비율은 산출물을 만들기 전에 거부됨
