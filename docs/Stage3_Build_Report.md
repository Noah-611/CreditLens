# Stage 3 고객 분석 마트 빌드 보고서

> 대출 신청정보, 외부 신용이력과 과거 납부기록을 고객당 한 행으로 통합한 V1·V2·V3 분석 마트의 실제 구축·검증 결과입니다. 피처 분포와 `TARGET` 비교 통계는 `train` 파티션만 사용했습니다.

## 결과 요약

- V1·V2·V3 모두 **307,511명, 고객당 한 행**으로 생성되었습니다.
- 고객 키, `TARGET`, `SPLIT`과 이전 버전의 모든 공통 컬럼이 그대로 보존되었습니다.
- 외부 신용이력은 **263,490명, 1,465,308행**을 고객 단위로 집계했습니다.
- 과거 납부이력은 **291,643명, 납부 이벤트 11,591,592행**을 **할부 일정 11,026,627건**으로 먼저 합친 뒤 고객 단위로 집계했습니다.
- 신청 이후를 가리키는 이력은 사용하지 않았습니다. 양수인 `DAYS_CREDIT_UPDATE` 17행은 bureau 집계에서 제외했습니다.
- 전체 빌드는 **87.684초**, 프로세스 최대 RSS는 **2,300.25 MiB**였습니다.
- Stage 3 신규 피처 79개의 분포와 단변량 관계는 train 215,258명만 사용해 분석했습니다.
- 데이터 계약, 계보와 합성 데이터 대사를 포함한 전체 자동 테스트가 통과했습니다.

기계 판독 가능한 상세 결과는 `reports/stage3_build_summary.json`과 `reports/stage3_feature_profile.json`에 기록되어 있습니다. 두 파일에는 고객 ID나 행 단위 금융정보가 포함되지 않습니다. 데이터 구조와 산식은 [분석 마트 명세](Analysis_Mart_Spec.md)와 [피처 사전](Feature_Dictionary.md)에서 확인할 수 있습니다.

## 데이터 계보와 집계 단위

```text
application_train + customer_splits
                │
                └── 신청정보 정제·파생 ─────────────── V1
                                                      │
bureau ── 신청 이후 갱신 제외 ── 고객 집계 ───────────┴── V2
                                                         │
installments ── 할부 일정 집계 ── 고객 집계 ─────────────┴── V3
```

- V1은 대출 신청 한 건을 고객 한 행으로 유지하면서 sentinel·구조적 결측 플래그와 신청정보 비율 피처를 추가합니다.
- V2는 bureau를 `SK_ID_CURR`별로 먼저 집계하고 V1에 LEFT JOIN합니다.
- V3는 installments의 분할납부를 할부 일정 단위로 먼저 합친 후 고객별로 다시 집계하고 V2에 LEFT JOIN합니다.
- 각 버전은 `SK_ID_CURR`, `TARGET`, `SPLIT`을 메타데이터로 보존합니다. 모델 입력에서는 이 세 컬럼과 정책상 제외한 `CODE_GENDER`를 사용하지 않습니다.

## 신청정보 정제와 파생

- 전체 application에서 `DAYS_EMPLOYED=365243` sentinel 55,374건을 실제 근속기간으로 사용하지 않고 `NULL`로 바꾼 뒤 `DAYS_EMPLOYED_SENTINEL` 플래그를 추가했습니다.
- 차량을 보유하지 않아 `OWN_CAR_AGE`가 적용되지 않는 경우와 차량 보유자의 일반 결측을 서로 다른 플래그로 구분했습니다.
- 소득 대비 대출금액·연간상환액, 대출금액 대비 상품가격, 가족 1인당 소득, 나이·재직기간과 외부 신용평가 평균 등의 행 단위 파생값을 만들었습니다.
- V1 생성에는 중앙값, 분위수처럼 데이터에서 학습하는 통계를 사용하지 않았습니다. 동일한 산식을 모든 split에 적용하되 분포 분석과 처리 결정은 train으로 제한했습니다.

## 외부 신용이력 집계

- 원본 bureau 1,716,428행 중 현재 신청 고객과 연결되고 예측 시점 조건을 통과한 **1,465,308행**을 사용했습니다.
- 집계된 이력이 있는 현재 신청 고객은 **263,490명**입니다.
- `DAYS_CREDIT > 0`인 행은 0건이었습니다.
- `DAYS_CREDIT_UPDATE > 0`인 17행은 신청 이후 갱신 가능성이 있어 집계 대상에서 제외했습니다.
- 금액 피처는 통화 간 단순 합산을 피하기 위해 `currency 1` 행만 집계하고, 비주통화 행 수는 별도 피처로 남겼습니다.
- 이력이 없는 고객은 `BUREAU_HAS_HISTORY=0`, 건수 피처 0으로 표현합니다. 금액·평균·비율은 관측되지 않았다는 의미를 보존하도록 `NULL`로 둡니다.
- bureau 피처 계약 위반은 0건이었습니다.

## 과거 납부이력 집계

납부 원본에는 하나의 할부 일정이 여러 납부 이벤트로 나뉜 분할납부가 있습니다. 납부 이벤트를 바로 고객별로 세면 연체·미달납부 비율의 분모가 왜곡되므로 두 단계로 처리했습니다.

1. `(SK_ID_CURR, SK_ID_PREV, NUM_INSTALMENT_VERSION, NUM_INSTALMENT_NUMBER)`로 납부 이벤트를 할부 일정 단위로 합칩니다.
2. 할부 일정별 예정금액, 총 납부금액, 마지막 납부일, 지연일과 납부차액을 계산합니다.
3. 할부 일정을 다시 `SK_ID_CURR` 기준으로 집계합니다.

| 집계 단계 | 규모 |
|---|---:|
| 현재 신청 고객의 납부 이벤트 | 11,591,592행 |
| 중복·분할납부를 합친 할부 일정 | 11,026,627건 |
| 납부이력이 있는 고객 | 291,643명 |

- 신청 이후 예정일 또는 실제 납부일을 가진 행은 각각 0건이었습니다.
- `SK_ID_PREV`가 둘 이상의 고객에 연결된 위반은 0건이었습니다.
- 동일 할부 일정 안의 예정일·예정금액 불일치는 0건이었습니다.
- 실제 납부일과 납부금액의 결측 불일치는 0건이었습니다.
- 납부정보 결측은 실제 0원 납부와 구분합니다. 결측 이벤트가 포함된 할부 일정의 납부금액·지연일·납부차액·납부비율은 `NULL`로 보존합니다.
- 이력이 없는 고객은 `INST_HAS_HISTORY=0`, 건수 피처 0으로 표현하고 금액·평균·비율은 `NULL`로 둡니다.
- installments 피처 계약 위반은 0건이었습니다.

합성 데이터 자동 테스트에서는 다음 경우를 별도로 대사했습니다.

- 분할납부 이벤트가 하나의 할부 일정으로 합쳐지는지 확인
- 실제 0원 납부와 납부정보 결측이 구분되는지 확인
- 비주통화 금액이 통화 합계에서 제외되는지 확인
- 이력 없음의 건수 0과 금액·비율 `NULL` 규칙 확인
- 잘못된 split, 신청 이후 이력과 불일치 할부 일정 거부 확인
- 빌드 요약에서 고객 ID와 절대 경로가 제외되는지 확인

전체 자동 테스트가 통과했습니다.

### 분포 특성

- 비음수이면서 오른쪽 꼬리가 긴 피처 21개를 `log1p` 비교 후보로 확인했습니다.
- 하나의 값이 관측치의 99% 이상을 차지하는 피처는 9개였습니다. 희소한 연체·결측 사건일 수 있으므로 빈도만으로 자동 제거하지 않습니다.
- 납부비율은 분할납부·초과납부 때문에 1보다 클 수 있습니다. 비율 피처를 일괄적으로 0~1 범위에 자르지 않습니다.
- 극단값은 실제 금융 규모나 드문 사건일 수 있으므로 행 삭제 기준으로 사용하지 않습니다.

## Stage 4 전처리 결정

Stage 3 분석 결과를 바탕으로 다음 원칙을 적용합니다.

1. 결측 대치값과 결측 플래그 사용 여부는 train에서만 학습·결정합니다.
2. 이력 없음은 `HAS_HISTORY=0`과 건수 0으로 유지하고, 금액·평균·비율의 `NULL`을 임의로 0으로 바꾸지 않습니다.
3. 비음수 오른쪽 꼬리 피처의 `log1p`는 선형 모델에서 비교하고 트리 모델에는 원값을 유지합니다.
4. 이상치 행을 삭제하지 않습니다. 선형 모델에 clipping이 필요하면 train 분위수로만 경계를 정합니다.
5. 납부비율처럼 업무상 1을 넘을 수 있는 비율은 일괄 clipping하지 않습니다.
6. `TARGET`별 단변량 차이는 분석 신호로만 사용하고 인과 설명이나 단독 피처 선택에 사용하지 않습니다.
7. validation은 학습된 변환과 후보 모델 비교에만 사용하고 test는 최종 평가 전까지 봉인합니다.

## 한계

- Home Credit 데이터는 공개 익명 해외 과거 데이터이므로 현재 국내 금융환경에 그대로 일반화할 수 없습니다.
- 신뢰할 수 있는 실제 신청 날짜가 없어 시간 순서 기반 out-of-time 검증은 수행할 수 없습니다. 상대 일수가 신청 이후를 가리키지 않는지만 검증했습니다.
- bureau 금액 합계는 통화 혼합을 피하기 위해 `currency 1`로 한정했습니다. 비주통화 이력의 금액 규모는 직접 반영하지 않습니다.
- 납부 이벤트를 할부 일정으로 합치는 키는 제공된 식별자 조합에 의존합니다. 원본에서 일정 내부 예정일·금액 일관성을 검사했지만 실제 업무 시스템의 거래 정의와 다를 수 있습니다.
- 결측과 이력 없음은 의미가 다를 수 있으나 공개 데이터만으로 모든 원인을 확정할 수 없습니다.
- train 단변량 분석은 모델 성능, 확률 보정, 안정성이나 공정성을 증명하지 않습니다.
- 자원 사용량은 현재 로컬 환경의 한 번의 실행 결과이며 다른 환경의 성능 보장이 아닙니다.
- 이 단계에서는 결측 대치·인코딩을 학습하거나 모델을 학습·선택하지 않았습니다.

다음 단계에서는 train에만 적합하는 전처리 파이프라인을 만들고 Dummy Classifier와 기준 머신러닝 모델을 동일한 평가 체계에서 비교합니다.
