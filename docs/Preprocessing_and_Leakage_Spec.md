# CreditLens 전처리·데이터 누수 점검 명세

> Stage 2 학습 파티션 EDA와 Stage 3 고객 분석 마트 검증을 근거로 정한 전처리 경계와 누수 방지 원칙입니다. Stage 4에서 이 원칙을 적용한 전처리·평가 기반과 기준 모델 학습 경로를 구현했으며, train 학습·validation 비교까지 완료했습니다.

## 예측 시점

CreditLens의 예측 시점은 **현재 대출 신청을 심사하는 시점**입니다. 이 시점에 알 수 있는 신청정보와 과거 이력만 입력 후보로 사용합니다. 현재 신청 이후에 만들어지는 정보와 정답을 직접·간접적으로 나타내는 정보는 사용할 수 없습니다.

## 데이터 사용 경계

| 데이터 | Stage 2 허용 작업 | 금지 작업 |
|---|---|---|
| train | EDA, 처리 규칙 설계, 향후 전처리기 `fit` | 원본 수정 |
| validation | 분할 무결성과 TARGET 층화 확인 | EDA 근거 생성, 전처리기 `fit` |
| test | 고객 수·배타성·TARGET 보존 확인 | 피처 EDA, 처리 결정, 모델·임계값 선택, 중간 성능 확인 |

validation은 Stage 4 이후 학습 데이터에서 만든 변환과 모델을 비교하는 데 사용합니다. test는 Stage 8에서 고정된 설정으로 한 번 평가합니다.

## 컬럼 사용 정책

| 구분 | 컬럼·그룹 | 정책과 이유 |
|---|---|---|
| 항상 제외 | `TARGET` | 정답 레이블이며 입력에 포함하면 직접 누수입니다. |
| 항상 제외 | `SK_ID_CURR` | 조인·추적용 식별자이며 모델 피처로 사용하지 않습니다. |
| 모델 입력 제외 | `CODE_GENDER` | 직접적인 성별 사용을 피하고 공정성 분석용으로만 로컬 보존합니다. `XNA` 3건은 별도 범주로 관찰합니다. |
| 조건부 사용 | `DAYS_BIRTH` | 신청 시점 정보지만 연령에 따른 성능 차이를 별도로 점검합니다. |
| 조건부 사용 | 가족·자녀·교육·직업·주거·지역 변수 | 상환능력 정보와 사회적 대리변수 가능성이 함께 있어 Stage 6 집단별 성능 점검 대상입니다. |
| 조건부 사용 | `EXT_SOURCE_1~3` | 신청 시점 외부 신용점수로 보이지만 출처·산식과 높은 결측률을 기록하고 버전 비교에서 의존도를 확인합니다. |
| 사용 가능 | 신청금액·소득·계약·보유자산·신청시각 변수 | 현재 신청 시점에 관측 가능한 범위에서 사용합니다. |
| 사용 가능 | `bureau`, `installments_payments` 파생값 | 현재 신청일과 그 이전 이력만 고객 단위로 집계합니다. 신청 이후 갱신된 bureau 행은 제외하고 미래 납부 상대일이 없음을 전체 데이터에서 검사했습니다. |

공정성 관련 그룹은 행 단위로 Git에 기록하지 않고 집계 성능만 보고합니다. 이 정책은 법률 판단이 아니라 공개 데이터 분석을 위한 보수적인 설계 선택입니다.

## 학습 파티션 관찰 요약

- 분석 고객: 215,258명
- EDA 분석 피처: 120개(`SK_ID_CURR`, `TARGET` 제외)
- 수치형 104개, 범주형 16개
- 결측이 있는 피처 67개
- 결측률 50% 이상 피처 41개
- 99% 이상 같은 값인 거의 상수 피처 18개
- 고유값 3개 이상인 72개 수치 후보 기준, 절대 Pearson 상관계수 0.95 이상 피처 쌍 45개
- 104개 수치형 전체 단순 계산에서는 `DAYS_EMPLOYED`와 `FLAG_EMP_PHONE`의 sentinel 구조 쌍을 포함해 46개
- train의 `DAYS_EMPLOYED=365243`: 38,564건(17.9152%)
- 이 sentinel은 train에서 `ORGANIZATION_TYPE=XNA`와 모두 함께 나타남
- 0.1% 미만 희소 수준이 있는 범주형 피처 6개

고결측·고상관·거의 상수라는 이유만으로 Stage 2에서 자동 삭제하지 않습니다. 삭제 여부는 업무 의미와 이후 validation 성능을 함께 보고 결정합니다.

## 수치형 처리 원칙

1. 문자열 혼입과 무한값은 입력 계약 오류로 처리합니다.
2. 일반 결측은 train에서 계산한 중앙값을 기본 후보로 사용합니다.
3. 결측 자체에 의미가 있을 수 있으므로 결측 여부 플래그를 함께 검토합니다.
4. `DAYS_EMPLOYED=365243`은 실제 근속일이 아니므로 결측으로 바꾸고 `DAYS_EMPLOYED_SENTINEL` 플래그를 만듭니다.
5. `OWN_CAR_AGE` 결측 141,865건 중 `FLAG_OWN_CAR=N`인 141,862건은 구조적 해당 없음으로 분리하고, 일반 중앙값 대치를 적용하지 않습니다. `OWN_CAR_AGE_NOT_APPLICABLE` 플래그를 만들고 계산용 대체값은 피처 사전에 기록합니다.
6. 차량 보유자 73,396명 중 `OWN_CAR_AGE`가 결측인 3건에는 별도 결측 플래그를 만들고, Stage 4 전처리기에서 train 차량 보유자의 유효 연식 중앙값으로 대치합니다.
7. `DAYS_*`의 신청일 기준 부호를 보존합니다. 연·월 단위 변환은 Stage 3 피처 산식에 기록합니다.
8. 극단값만으로 고객 행을 삭제하지 않습니다.
9. 오른쪽 꼬리가 긴 비음수 금액·건수는 `log1p` 후보로 검토합니다.
10. 선형 모델은 `StandardScaler(with_mean=False)`를 적용합니다. `RobustScaler`는 사분위 범위가 0인 희소 금액 피처를 수천만 단위로 남겨 기준 Logistic Regression을 불안정하게 만들어 채택하지 않았습니다. train 분위수 기반 clipping은 후속 개선 실험으로 남기며 트리 모델에는 불필요한 스케일링을 적용하지 않습니다.

중앙값, 분위수와 스케일 값은 모두 train에서만 계산합니다.

## 범주형 처리 원칙

1. 실제 결측은 문자열 `__MISSING__`으로 명시합니다.
2. 원본의 `XNA`, `Unknown`은 실제 관측값이므로 임의로 결측과 합치지 않습니다.
3. train의 0.1% 미만, 즉 현재 기준 216명 미만인 수준은 `__RARE__` 통합 후보로 둡니다.
4. validation·test에서 처음 등장한 수준은 `handle_unknown="ignore"`로 처리합니다.
5. 희소범주 기준과 범주 목록은 train에서만 `fit`합니다.
6. 현재 Logistic Regression과 Random Forest 기준 모델 모두 동일한 원-핫 인코딩을 사용합니다. 모델 계열별 차이는 수치형 스케일링 여부뿐입니다.

## 파이프라인 경계

Stage 2에서는 정책만 확정했고, Stage 4에서 아래 순서를 지키는 전처리·모델 파이프라인을 구현했습니다. 실제 학습 모델과 validation 예측값은 Git에서 제외되는 로컬 `models/stage4/` 아래에만 저장합니다.

1. train에서 sentinel·결측·희소범주 규칙을 `fit`
2. 같은 객체로 train과 validation을 `transform`
3. validation 결과로 정책과 모델을 선택
4. 최종 선택 전까지 test 변환·평가 금지
5. Stage 8에서 고정된 파이프라인으로 test를 한 번 평가

교차검증을 사용할 때도 각 fold의 학습 부분에서만 전처리기를 `fit`합니다.

## 누수 점검 체크리스트

- [x] `TARGET`, 고객 ID와 행 추적용 ID가 입력 피처에서 제외됨
- [x] 현재 신청 이후 생성된 정보가 없음
- [x] 보조 테이블의 상대 일수가 신청일 이후를 가리키지 않음
- [x] 고객 이력을 집계한 뒤 고객당 한 행이 유지됨
- [x] train·validation·test 고객이 서로 겹치지 않음
- [x] 결측 대치값·희소범주 규칙과 스케일 값이 train에서만 계산됨
- [x] 피처 선택과 모델 선택에 test 결과를 사용하지 않음
- [x] 문서와 JSON에 고객 ID나 행 단위 금융정보가 없음

## Stage 3 반영 결과

- `DAYS_EMPLOYED=365243`은 `NULL`로 바꾸고 sentinel 플래그를 생성했습니다.
- `OWN_CAR_AGE`는 대치하지 않고 구조적 해당 없음과 일반 결측 플래그만 생성했습니다.
- bureau의 `DAYS_CREDIT > 0` 행은 0건이었고, `DAYS_CREDIT_UPDATE > 0`인 17행은 집계에서 제외했습니다.
- installments의 신청 이후 예정일·납부일은 0건이었습니다.
- 납부 이벤트는 `(SK_ID_CURR, SK_ID_PREV, NUM_INSTALMENT_VERSION, NUM_INSTALMENT_NUMBER)` 납부회차로 먼저 합친 뒤 고객 단위로 집계했습니다.
- 납부일·납부금액 결측은 0원 납부로 바꾸지 않았습니다. 이력 없음은 건수 0, 금액·평균·비율 `NULL`, 별도 이력 플래그 0으로 구분했습니다.
- V1·V2·V3 모두 고객당 한 행이며 고객 키·`TARGET`·split과 앞 버전 공통 컬럼이 보존됐습니다.
- 파생 피처 분포와 TARGET 관계는 train 215,258명에서만 계산했고 validation·test 피처 행은 사용하지 않았습니다.

## Stage 4 구현 현황

- `SK_ID_CURR`, `TARGET`, `SPLIT`을 메타데이터로 분리하고 `CODE_GENDER`를 모델 입력에서 제외하는 V1·V2·V3 피처 역할 계약을 구현했습니다.
- 공개 로더는 train과 validation만 반환하며 test split 요청을 명시적으로 거부합니다.
- 기본 마트는 Stage 3 요약의 스키마·행 수·split별 건수·파일 해시와 자동 대조합니다.
- 수치형 중앙값 대치와 결측 플래그, 범주형 `__MISSING__`·`__RARE__` 처리와 미등록 범주 무시 규칙을 train에만 `fit`합니다.
- Stage 3에서 결측으로 바꾼 `DAYS_EMPLOYED` sentinel은 train 중앙값과 결측 플래그로 처리합니다. 차량 미보유자의 `OWN_CAR_AGE`는 0으로, 차량 보유자의 결측 차령은 train의 유효한 보유자 중앙값으로 대치합니다.
- 선형 모델에는 희소 행렬을 유지하는 스케일링을 적용하고 트리 모델에는 불필요한 스케일링을 적용하지 않습니다.
- 공통 평가 모듈에 ROC-AUC, PR-AUC, KS, Gini, Brier Score, 임계값 지표와 Top-K 지표를 구현했습니다.
- Dummy Prior, V1·V2·V3 Logistic Regression과 V3 Random Forest를 train으로 학습하고 동일한 validation에서 비교했습니다.
- 현재 튜닝 전 기준에서는 V3 Logistic Regression이 ROC-AUC 0.7585, PR-AUC 0.2424, KS 0.3908로 가장 높았습니다. 이는 최종 모델 선택 결과가 아닙니다.
- 저장된 validation 점수로 ROC·PR·Calibration 곡선, 위험도 decile과 Top-K 상세 분석을 완료했습니다. Calibration은 보정 필요성 진단이며 보정기나 운영 cutoff를 학습·선택하지 않았습니다.
- 비음수 오른쪽 꼬리 피처의 `log1p`와 선형 모델용 clipping은 후속 개선 실험에서 train 내부 비교 대상으로 남깁니다.
- 납부비율은 실제 초과납부로 1보다 클 수 있으므로 일괄적으로 0~1에 자르지 않습니다.
- 행 단위 가공 데이터와 직렬화된 학습 모델은 `data/processed/`, `models/`에만 저장하고 Git에서 제외합니다. 공유 문서에는 고객 ID가 없는 집계 성능만 기록합니다.

구현된 입력·전처리·평가 계약의 상세 정의는 [Stage 4 전처리·평가 명세](Stage4_Preprocessing_and_Evaluation_Spec.md), 실제 기준 모델 결과는 [Stage 4 기준 모델 학습 보고서](Stage4_Baseline_Model_Report.md), 상세 validation 진단은 [Stage 4 Validation 분석 보고서](Stage4_Validation_Analysis_Report.md)를 참고합니다.
